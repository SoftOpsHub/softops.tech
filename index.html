03 Zero Trust on AWSReference architecture A lean Zero Trust architecture built entirely as code, then attacked to prove it holds, at about $84 a month. Cloud security · Infrastructure as code · Adversarial validation

Proven under attack, not on paper.

Can a smaller organisation afford real Zero Trust? We built a reference architecture to find out, and signed it off on enforcement rather than configuration. The question isn't "does the rule exist?" but "does it hold when something pushes on it?"

  • Ten infrastructure modules with remote state and locking
  • Three-tier network with no NAT: no internet route from compute or data, at all
  • Every cloud call through nine private endpoints
  • Identity capped by permission boundaries that no admin override can exceed
  • TLS 1.3-only edge with WAF, three encryption domains, locked backups

03Method

Engineering-first means
you can check our work.

  1. We write it down first.

    Specs and design documents before code. A recent product revamp was specified as six design documents, each mapped to a release, before the first commit.

  2. You see everything.

    One live board holds every feature, bug and release, and it's open to you. A release report is a saved filter, not a document someone rebuilds on Friday afternoon.

  3. We measure before we promise.

    Load suites replay your app's real traffic before launch. Capacity is a number we've measured, not a hope.

  4. We prove security.

    We sign off on enforcement, not configuration. If a control hasn't been pushed on, we don't call it done.

  5. Everything is code.

    Infrastructure, deployments, release pipelines, even marketing films. If it can't be rebuilt from the repository, it isn't finished.

  6. AI in every stage.

    Our engineers work alongside AI agents in spec, code, test and review, under conventions and guardrails written into every repository. It makes us faster without lowering the bar.
